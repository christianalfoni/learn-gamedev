The arena

The fixed multi-floor level everything else happens inside. Floors you can drop through, gaps enemies fall through, and a shape you can re-tune later by moving tiles. No enemies, no player, no shooting — just the space.

Godot 4.3+ 60–90 min 7 steps base game

What the game will have that it doesn't now

  • A multi-floor arena with collision, built from a tileset rather than hand-placed shapes.
  • One-way floors — land on them from above, pass through from below.
  • Gaps positioned deliberately, because gap placement is this game's difficulty knob and you'll be moving them for the rest of the project.
  • Marked spawn and drain lines at the top and bottom for later assignments to hook onto.

What this deliberately leaves plain

No background layers, no parallax, no decoration, no lighting. The arena's shape is a mechanics decision and gets built properly here; how it looks is a separate job for when the art sections of the document are written.

You need a tileset PNG to start

Any uniform grid with no padding — 16 × 16 or 32 × 32. If you don't have one, take a CC0 pack from Kenney. Placeholder tiles are correct here: this assignment is about shape, and shape is easier to judge when the art isn't distracting you.

Step 1

Project and import settings

8 min

New 2D project. Drop the tileset PNG in, select it in the FileSystem dock, open the Import tab and turn Filter and Mipmaps off, then Reimport. Or set it project-wide: Project Settings → Rendering → Textures → Canvas Textures → Default Texture Filter → Nearest.

Then set the window to something honest — Project Settings → Display → Window, viewport 480 × 270, Stretch Mode: canvas_items, Aspect: keep. This game is a single fixed arena, so the viewport size is roughly the arena size, and picking it now saves you rebuilding the level later.

Why the viewport decides the arena

Everything in this game has to be visible at once — you're making routing decisions based on where enemies are, and you can't route around what you can't see. So there's no camera following anything and no scrolling. At 480 × 270 with 16-pixel tiles that's a 30 × 17 tile arena, which is a good size: four or five floors with room to move between them.

Step 2

TileMapLayer and the TileSet

12 min

New 2D Scene, root node Node2D named Arena, saved as arena.tscn. Set it as the main scene when Godot offers.

Add two TileMapLayer children:

  • Solid — walls, the outer boundary, anything you can't pass through.
  • Floors — the one-way platforms you land on and drop through.

On Solid, set Tile Set → New TileSet, open it, and set the tile size to match your PNG. In the bottom panel's TileSet tab, add an Atlas source with +, choose your PNG, and accept the offer to create tiles automatically.

Then select Floors and assign it the same TileSet resource — drag it across from Solid's inspector. One tileset, two layers.

Why two layers rather than one

Solid tiles and one-way tiles need different collision, and collision lives on the tile in the TileSet. Splitting them into two layers means you paint with intent — "this is a wall" versus "this is a floor" — instead of trying to remember which tile in the atlas you gave which property to. It also lets a later assignment hide or query one without the other.

Step 3

Collision on the solid tiles

10 min

In the TileSet tab, select the TileSet resource itself and add two Physics Layers with +:

  • Physics Layer 0 — leave its Collision Layer as layer 1. This is walls.
  • Physics Layer 1 — set its Collision Layer to layer 2 only, and untick layer 1. This is the one-way floors, in step 4.

Now select the atlas source, switch the tile editor to Select mode, and drag-select every tile you'll use as a wall or solid block. In the inspector you'll see Physics → Physics Layer 0 with a small polygon editor — use its reset button to fill the tile with a full rectangle. One click per selection, not per tile.

Why two physics layers rather than one

Because the player will need to selectively ignore the floors in order to drop through them, while never being able to ignore a wall. Selective ignoring is done by switching off one bit of a collision mask, so walls and floors have to be on different bits. Put them both on layer 1 and the moment the player drops through a floor they'd also fall straight out through the side of the arena.

Why this beats hand-placed collision

Collision now travels with the tile. Paint a wall anywhere and it's solid; move it and the collision moves too. When you re-tune this arena later — and you will, repeatedly, because gap placement is the difficulty — you're moving tiles rather than keeping a parallel set of collision shapes in sync.

Step 4

One-way floors

12 min

Pick a distinct tile — a thin platform, a different colour, anything you can tell apart at a glance. Select it, and this time fill in Physics → Physics Layer 1 instead of layer 0, using the same reset-to-rectangle button. Leave its Physics Layer 0 empty: this tile is a floor, not a wall.

Then, with the tile still selected, find Physics Layer 1 → One Way and turn it on.

One-way collision means the shape is only solid from one direction. The default direction is downward, which is what you want: things land on it from above and pass straight through from below. There's a One Way Margin next to it, default 1.0 — leave it.

Only the floors, never the outer walls

It's tempting to make everything one-way and save a tile. Don't — the arena's boundary has to be genuinely solid or enemies will walk out of the sides and the drain at the bottom will never see them. Walls solid, floors one-way, and keep them visually distinguishable so you can see at a glance which is which while painting.

Step 5

Paint it — the gaps are the game

15 min

Paint a solid boundary on Solid — left wall, right wall, and a ceiling with an opening at the top for enemies to enter. Leave the bottom open; that's the drain.

Then paint four or five floors on Floors, each with one or two gaps in it. This is the part worth taking slowly, because those gaps are the only difficulty lever you have:

  • Stack the gaps vertically and you've built a chute — enemies drop almost straight to the bottom and you have seconds to react.
  • Offset them and an enemy has to walk the length of each floor to find the next hole, which is slow, predictable, and gives you time to get there.
  • A floor with no gap at all is a holding pen: enemies pace back and forth on it and pile up until you deal with them.

Start with offset gaps. It's the forgiving version, and you want the first playable build to be winnable while everything else is still rough.

Why this is worth getting deliberate about

In most platformers the level is content. Here it's the balance sheet. Because enemies have no intelligence — they walk, turn at walls, and fall off whatever edge they meet — the only thing deciding how fast pressure arrives at the bottom is where you cut the holes. That means you can retune the entire difficulty of the game by moving four tiles, without touching a line of code.

Step 6

The spawn line and the drain line

8 min

Two Marker2D nodes and one Area2D, so later assignments have somewhere to attach without rummaging through the tilemap:

  • SpawnLeft and SpawnRight — Marker2Ds just below the ceiling opening, a little in from each wall. Enemies will appear at one of these.
  • Drain — an Area2D with a wide, flat CollisionShape2D spanning the full width of the arena, positioned just below the lowest floor, off the bottom of the visible area.

Give the Drain a recognisable name and leave it at that — the logic that fires when something enters it belongs to a later assignment, and putting it here would tangle two jobs.

Put the drain below the visible area, not at the last floor

If the drain sits level with the bottom floor, an enemy walking along that floor is already inside it. Place it below everything, so the only way to touch it is to have genuinely fallen out of the arena. Ten pixels of clearance is plenty.

Step 7

Drop things through it

12 min

This is the assignment. You can't test an arena by looking at it.

Add three or four RigidBody2D nodes near the top, each with a CollisionShape2D roughly enemy-sized and any sprite or a plain ColorRect so you can see them. Run the scene and watch what happens.

Watch forWhat it tells you
How long to reach the bottomYour baseline pressure. Count it out loud — that number is what later difficulty tuning moves.
Boxes landing on the one-way floorsPhysics Layer 1 and One Way are configured correctly.
Anything reaching the DrainThe route from top to bottom actually exists. Nothing else in the game works if it doesn't.
Boxes escaping through a wallA missing collision tile in the boundary, usually a corner.
A box that gets stuck foreverA pocket with no exit. Fine for a holding pen, fatal if it's the only route down.

Then move the gaps and drop them again. Try the chute version — all gaps stacked — and count again. Feeling the difference between three seconds and twelve is the point of this step, and it's the intuition you'll be using every time you rebalance the game.

What this test can't tell you

Falling boxes tumble; walkers don't. A box can roll through a gap a walking enemy would stride past, so treat these times as a rough floor rather than a measurement. The real numbers arrive when there's something that walks — and the arena is likely to need one more pass then.

Delete the boxes when you're done, and write down the descent time you settled on. Every later balance decision is relative to it.

That's the assignment

The game now has the space it happens in, and — more usefully — you know that its difficulty lives in tile placement rather than in code. That's a lever you can pull in thirty seconds, for the rest of the project.
